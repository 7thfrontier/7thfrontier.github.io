Sliders that fit a restored value · 2026-11-04

- **A slider now shows a value that a link restored outside its range.** Opening a link with a value beyond a slider's own range, such as a Superformula n1 of 0.02 on a slider that starts at 0.1, left the thumb pinned at the slider's end while the badge showed the real value, and the first nudge jumped from that end. The slider now stretches to include the restored value, so the thumb sits on it and one step moves one notch from it. It goes back to its usual range once a value fits again.
- **Undo now brings back a variation sheet that was closed right after it appeared.** Closing a variation sheet with its Close button or Escape within a second or two of making it dropped the sheet from history, so Undo went to the picture before the sheet instead of bringing the sheet back. The sheet is now kept in history however soon it is closed.
- **Test transcripts now show where each browser test's time goes.** Every browser test prints how long its browser took to start and to close, how long each page took to load, and how long the app took to boot, and the test runner prints the time each test started. A release check's record can then split the fixed start-up cost from the time spent testing, which is the number needed to judge whether reusing one warm browser across light tests is worth it. These lines appear only in tests the runner starts itself, so a command-line tool such as `render.mjs --list` prints none of them, even when a test runs it.
- **A change to a test helper now selects the tests that run a command-line tool built on it.** The release check already took the tests that start a tool importing a changed file directly. It missed a tool that reaches the file through other modules, so a change to the test render cache left out the preview tests that run the preview recorder. Now any tool that reaches the change, at any depth, counts, and a tool's file name no longer matches inside a longer test name.
- **Two gate-timing tests now run, and a test in `bin/` can no longer be forgotten.** The test of the time-left estimate for a running release check had been failing for two weeks without anyone seeing it, because no test run included it. Its fixture used fixed dates from before the machine last restarted, so the check read its running gate as one that had died. It now uses the current time, both gate-timing tests are registered, and the test registry check covers test files in `bin/` as well.
- **A failed exit-code check in the landing tool's test now shows why.** Each such check prints the land's exit code and the end of its output when it fails, so a one-off failure can be diagnosed without running it again.
