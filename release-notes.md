One Export image tab, a proof before a long export, and Render history · 2026-10-20

- **A proof before a long export.** A large export first renders a small piece at its final pixel size beside the same piece of the screen, says whether it comes out brighter or darker than the screen, and waits for Export or Cancel. Escape-time, formula and 3D fractals show their exact pixels; Buddhabrot, attractors, flames and IFS show the whole picture small, for tone only, and say so when there is not enough memory for the export.
- **One Export image tab.** The Quick and Print / Hi-Res tabs are now one tab: pick a format and a size as before, and open Print options for physical size and DPI, supersampling, Letterbox or Extend, 3D projection and EXR. The Resolution row gains 8K and 16K, and Custom now reaches 32768 px. A file at a pixel size renders through one path, so the same settings always give the same file; supersampling, physical size and EXR keep their own path.
- **The PSL₂(7) Cayley graph reads as Klein's quartic.** Its 168 vertices now lie in the Poincaré disk as one patch of the truncated heptagonal tiling: 14-sided faces for the order-7 rotation, small triangles for the order-3 generator, and faint edges where the patch is glued back into the closed surface. Before, it was a dense 3D cloud.
- **Render history.** The catalog's new History chip, also under Render history in the menu, shows the last 16 views you rendered with a thumbnail each, newest first. One click returns to the exact state that drew it. The list lives in memory and starts over when you reload.
- **The 4D projection badge points at the Projection control.** Its tooltip told you to add a flag to the address bar; it now names the 4D Projection control in the Inspector, which switches between Stereographic and Schlegel.
- **No more constant redrawing while idle on some graphics setups.** When the browser cannot keep the last frame (a fallback some GPUs and drivers use), the layer and eyepiece thumbnails each triggered a fresh render, which scheduled the next thumbnail, so the picture redrew about twice a second forever, costing battery and up to 60 ms of main-thread time each time on a phone.
- **A drag at deep zoom no longer snaps back before it lands.** When the picture is computed on the CPU (deep zooms, with WebGPU off), letting go of a drag showed the old picture back where the drag started until the new frame arrived, which can take seconds, and then it jumped to where you dropped it. It now stays where you let go while the new frame renders.
